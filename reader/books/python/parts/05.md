# Funções e escopo
## Uma tarefa com nome
Função agrupa uma operação reutilizável. `def dobro(valor): return valor * 2` define o contrato: recebe um valor e devolve outro. Chamá-la com `dobro(4)` produz 8. Prefira funções curtas, com nome que indique o que fazem. Uma função que lê teclado, calcula e grava arquivo ao mesmo tempo é mais difícil de testar do que três pequenas funções com responsabilidades separadas.
## Parâmetros e retorno
```python
def calcular_media(notas):
    if not notas:
        return None
    return sum(notas) / len(notas)
```
O parâmetro `notas` recebe a lista passada na chamada. `return` entrega o resultado e encerra a função; sem ele, a função devolve `None`. Escolhemos `None` para lista vazia porque uma média não existe nesse caso. Documente esse contrato e teste ambos os ramos. Imprimir uma média não é igual a devolvê-la.
## Argumentos por nome
`def desconto(preco, taxa=0.10): ...` oferece valor padrão. Chamadas como `desconto(100, taxa=0.15)` mostram intenção. Padrões são avaliados uma vez na definição; não use lista mutável como valor padrão para acumular resultados. Prefira `None` e crie lista dentro da função quando necessário. Valide unidade e intervalo da taxa, pois 15 pode significar 15% ou fator 15 dependendo do contrato.
## Escopo local
Nomes criados dentro da função são locais. Alterar `total` ali não modifica automaticamente um `total` fora. Variáveis globais mutáveis tornam funções dependentes de estado oculto e atrapalham testes. Passe dados necessários por parâmetros e devolva resultados. Em programas grandes, algum estado compartilhado pode existir, mas deve ser administrado explicitamente. Essa disciplina ajuda a entender a origem de cada valor.
## Efeitos colaterais
Uma função pura devolve resultado sem mudar dados externos para as mesmas entradas. `somar(a, b)` é exemplo simples. Uma função que altera uma lista recebida, grava arquivo ou envia requisição tem efeito colateral. Efeitos são necessários, mas devem aparecer no nome, contrato e testes. Para calcular uma nova lista de preços, devolver outra coleção costuma ser mais previsível que modificar a original silenciosamente.
## Documentação e tipos
Uma docstring descreve propósito e casos especiais logo após `def`. Anotações como `def dobro(valor: int) -> int:` comunicam intenção a pessoas e ferramentas; Python não força esses tipos automaticamente em toda chamada. Use exemplos testáveis na documentação. Se uma função pode devolver `None`, a anotação deve refletir isso. A documentação deve contar o que a função promete, não narrar linha por linha.

# Recursão e análise de algoritmo
## Problema dentro de problema
Recursão ocorre quando uma função chama a si mesma com uma entrada menor. Para somar de 1 a n, `soma(n) = n + soma(n-1)` até o caso base `soma(0) = 0`. Sem base ou sem aproximação dela, chamadas continuam até falhar. Desenhe a pilha para `soma(3)`: chamadas descem a 0, respostas voltam em ordem inversa.
## Exemplo legível
```python
def soma_ate(n):
    if n < 0:
        raise ValueError("n deve ser não negativo")
    if n == 0:
        return 0
    return n + soma_ate(n - 1)
```
Esse exemplo ensina a ideia, mas um laço ou fórmula pode ser melhor para n grande. Python limita profundidade de recursão. Não aumente esse limite para “consertar” algoritmo que não progride. Teste 0, 1, 4 e negativo.
## Custo de tempo
O laço que soma n valores faz trabalho proporcional a n, O(n). Uma fórmula matemática pode usar número fixo de operações, O(1), dentro de limites de representação. Notação de complexidade descreve crescimento, não tempo exato. Uma função que compara cada item com todos os outros tende a O(n²). Antes de otimizar, garanta saída correta e meça com dados representativos.
## Custo de memória
Uma lista nova com n elementos ocupa memória proporcional a n. Um gerador pode produzir valores sob demanda. Recursão usa pilha de chamadas, também custosa. Em arquivos grandes, ler tudo com `read()` pode ser inadequado; iterar linha por linha reduz pico de memória. A escolha depende do tamanho, da necessidade de reutilizar dados e da clareza do código.
## Busque o caso base
Recursão combina com árvores, estruturas aninhadas e divisão do problema. Para percorrer pastas, cada pasta contém arquivos e outras pastas; uma função pode processar subpastas. Mas links simbólicos e ciclos exigem cuidado. Antes de aplicar, defina base, redução e limite de profundidade. Muitos problemas simples ficam mais claros com `for`; recursão é ferramenta, não prova de sofisticação.
## Comparar soluções
Implemente soma com `for`, com recursão e, se fizer sentido, com fórmula. Teste os mesmos casos. Depois compare legibilidade, risco e crescimento. Uma solução matematicamente elegante pode esconder regras de domínio; uma solução rápida pode ser difícil de manter. Explique a escolha a um colega iniciante e veja se ele consegue prever comportamento para entrada vazia ou inválida.

# Módulos, pacotes e ambiente
## Não escreva tudo num arquivo
Módulo é um arquivo Python importável. `import math` traz funções como `math.sqrt(9)`. Um pacote organiza módulos sob um nome. Separar código em arquivos com funções coerentes facilita teste e reuso. Evite chamar seu arquivo de `math.py`, `json.py` ou `random.py`, pois ele pode esconder o módulo padrão esperado. O erro resultante parece confuso até você inspecionar o caminho importado.
## Import explícito
```python
from math import sqrt
print(sqrt(81))
```
Prefira importações claras a `from modulo import *`, que torna difícil saber de onde veio cada nome. Código no nível superior de um módulo executa quando ele é importado; coloque demonstrações sob `if __name__ == "__main__":` para evitar efeitos indesejados. Uma função importável é mais fácil de testar do que um script que pede entrada imediatamente.
## Biblioteca padrão e terceiros
Python vem com biblioteca padrão: `pathlib`, `json`, `datetime`, `sqlite3`, `logging` e muitas outras. Pacotes externos como pandas precisam de instalação. Consulte a documentação antes de adicionar dependência: talvez a biblioteca padrão resolva bem o problema. Pacotes ampliam capacidades, mas trazem versões, licenças, atualizações e risco de cadeia de suprimentos para o projeto.
## Ambiente virtual
`python -m venv .venv` cria ambiente do projeto. Ative conforme sistema ou chame o executável dentro de `.venv` diretamente. Depois use `python -m pip install pacote` nesse ambiente. Confirme `python -m pip --version` e caminho do Python antes de instalar. Não coloque `.venv` no Git; registre dependências e instruções para recriá-lo. Projetos diferentes podem precisar de versões incompatíveis.
## UV no projeto
UV pode criar ambiente, resolver dependências e executar comandos de projeto. Num projeto novo, `uv init` e `uv add nome-do-pacote` são um caminho; `uv run python arquivo.py` usa o ambiente gerenciado. A sintaxe e opções evoluem: consulte a documentação oficial do UV instalada para sua versão. O conceito fundamental continua sendo declarar dependências, isolar projeto e reproduzir instalação.
## Reproduzir sem surpresas
Um arquivo de projeto descreve dependências; um lock registra versões resolvidas para reproduzir o ambiente. Faça commit do lock quando o fluxo do projeto pedir. Teste instalação do zero numa pasta limpa. Não copie `.venv` como único artefato de entrega, pois caminhos e plataforma variam. Para aplicativo empresarial, dependências devem ser revisadas e atualizadas com testes, não congeladas sem manutenção.
