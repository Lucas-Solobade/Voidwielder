# Objetos que guardam estado
## Quando criar uma classe
Uma classe reúne dados e comportamentos que pertencem ao mesmo conceito. Um `Carrinho` pode guardar itens e calcular total. Não crie classe para toda função simples; uma função livre pode ser suficiente. POO ajuda quando vários objetos do mesmo tipo têm estado próprio e regras associadas. Antes de codificar, descreva quais informações cada objeto deve conhecer e quais operações deve oferecer.
## Instância e método
```python
class Contador:
    def __init__(self):
        self.valor = 0

    def incrementar(self):
        self.valor += 1
```
`Contador()` cria uma instância; `c.incrementar()` altera seu estado. `self` refere-se à instância que recebeu a chamada. Dois contadores criados separadamente devem evoluir de forma independente. Teste isso: se ambos mudam juntos, você provavelmente guardou estado compartilhado na classe em vez de cada objeto.
## Invariantes do objeto
Uma conta bancária simplificada não deveria ficar com saldo negativo se a regra proíbe isso. Métodos podem validar antes de alterar. A invariante é a afirmação que deve valer depois de cada operação. Não exponha uma lista interna mutável sem necessidade; quem a recebe pode modificar o objeto por fora. Python usa convenções e propriedades para organizar acesso, mas a qualidade depende de um contrato claro e testes.
## Atributos de classe
Um atributo definido diretamente no corpo da classe é compartilhado, salvo quando uma instância o substitui. `itens = []` como atributo de classe pode fazer carrinhos diferentes dividirem a mesma lista, um bug clássico. Inicialize coleções por instância em `__init__`. Atributos de classe são úteis para constantes ou configurações realmente comuns. Crie dois objetos e teste se alterações num afetam o outro.
## Representação e identidade
`__repr__` pode ajudar depuração ao mostrar estado de forma clara, sem revelar senha ou token. `==` entre objetos depende de implementação; por padrão, duas instâncias distintas podem não ser consideradas iguais mesmo com dados parecidos. `is` pergunta se são o mesmo objeto. Defina igualdade apenas quando há significado de domínio, como duas coordenadas com os mesmos valores.
## Propriedades e validação
`@property` permite leitura por atributo com lógica controlada, como `pedido.total`. Um setter pode validar uma mudança, mas não esconda operação cara sob aparência de campo simples. Para objetos imutáveis, `dataclass(frozen=True)` pode evitar alterações após criação. Escolha interface previsível: alguém que usa a classe precisa saber quando ocorre cálculo, escrita ou chamada externa.
## Verifique e pratique
Crie dois contadores e mostre que incrementar um não muda o outro. Na atividade, implemente uma classe `Carteira` com saldo inicial e método `depositar` que rejeita valores negativos. Explique quais invariantes devem valer antes e depois da operação. Teste zero, positivo e negativo sem usar uma variável global para guardar saldo.

# Composição, herança e interfaces
## Composição primeiro
Composição constrói um objeto usando outros objetos. Um `Pedido` pode conter linhas de produto, sem ser um tipo de produto. A relação “tem um” difere de “é um”. Quando você modela apenas para reutilizar código, herança pode criar acoplamento difícil de mudar. Escreva as frases do domínio em português: “pedido tem itens”; “gato é animal”. Veja qual relação realmente existe.
## Herança simples
```python
class Animal:
    def falar(self):
        raise NotImplementedError

class Gato(Animal):
    def falar(self):
        return "miau"
```
A subclasse substitui um método. Isso só é útil quando quem usa `Animal` pode receber `Gato` sem quebrar contrato. Um tipo derivado que exige condições inesperadas viola essa expectativa. Herança múltipla existe em Python, mas traz resolução de métodos mais complexa; aprenda composição e contratos antes de adotá-la.
## Polimorfismo pelo comportamento
Uma função pode receber qualquer objeto com método `falar`, dependendo do contrato, mesmo sem herdar de `Animal`. Esse estilo, chamado tipagem de pato, valoriza capacidade observável. Protocolos de `typing` permitem declarar a interface para verificadores estáticos. Em código pequeno, documentação e testes podem bastar. Não force uma hierarquia grande só para permitir duas implementações simples.
## super e inicialização
`super().__init__()` chama implementação da classe base segundo a ordem de resolução. Use quando a base precisa inicializar estado. Teste a instância resultante, não suponha que herdar automaticamente prepara todos os atributos. Em herança múltipla, chamadas cooperativas exigem desenho cuidadoso. Se isso parecer desproporcional ao problema, composição provavelmente oferece caminho mais simples e explícito.
## Classes abstratas
`abc.ABC` e `@abstractmethod` podem exigir métodos antes de instanciar uma classe derivada. Isso ajuda bibliotecas ou arquiteturas com contratos estáveis, mas não é obrigatório para todo projeto. Uma interface só agrega valor se consumidores precisam trocar implementações. Exemplo: salvar relatório num arquivo ou enviar a um armazenamento remoto por um contrato comum.
## Evite hierarquia frágil
Se cada nova regra exige substituir vários métodos da classe base, o desenho está rígido. Prefira objetos pequenos que colaboram. Teste comportamento de cada implementação com os mesmos casos. Em equipe, nomeie as responsabilidades e efeitos de cada método. Uma classe não deve misturar autenticação, cálculo, banco de dados e envio de email só porque tudo envolve “usuário”.
## Verifique e pratique
Desenhe um pedido que contém produtos e um gato que é animal. Explique por que as relações não são equivalentes. Na atividade, implemente dois tipos de desconto com mesmo método `aplicar(preco)` e use uma função que aceita qualquer um dos dois. Teste o contrato sem depender do nome concreto da classe.

# Dataclasses e desenho de modelos
## Menos repetição para dados
`@dataclass` gera métodos úteis para classes que representam dados. Ela pode criar `__init__`, `__repr__` e comparação de igualdade conforme opções. Não substitui validação de regras. Use para um registro como `Produto(nome, preco)` quando campos e significado são claros. Para comportamento rico, métodos comuns continuam possíveis. Escolha tipos das anotações e documente unidades.
## Exemplo de produto
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Produto:
    nome: str
    preco: float
```
`frozen=True` impede reatribuição normal dos campos após criar objeto, mas não torna profundamente imutável uma lista guardada dentro dele. O exemplo usa `float` para ensino; dinheiro real pede política de precisão, frequentemente `Decimal` ou centavos inteiros. Teste igualdade entre duas instâncias com mesmos campos.
## Padrões mutáveis
Em dataclass, use `field(default_factory=list)` para criar lista nova por instância. Um valor padrão mutável compartilhado produziria surpresa semelhante à do atributo de classe. Faça duas instâncias, acrescente item numa e veja a outra. Esse teste simples protege carrinhos, registros e configurações. Se o registro deve ser imutável, prefira tupla ou outro tipo imutável em vez de expor lista mutável.
## Serializar com critério
`dataclasses.asdict` transforma dataclass em dicionário recursivamente, mas não decide automaticamente formato público seguro. Uma classe pode conter dados internos ou sensíveis que não devem ir para API. Crie um esquema de saída explícito quando necessário. Bibliotecas como Pydantic ajudam validação e serialização de entradas e saídas, mas trazem dependência; leia a documentação da versão adotada e valide regras do domínio além dos tipos.
## Composição de modelos
Um `Pedido` pode ter lista de `ItemPedido`, e cada item aponta para produto e quantidade. Não calcule total num campo armazenado sem plano para manter consistência quando itens mudam. Uma propriedade calculada ou método explícito reduz divergência. Se o total precisa ficar congelado para auditoria, registre-o na confirmação do pedido e preserve histórico. Modelagem é sobre regras do negócio, não apenas sintaxe da classe.
## Protocolos e evolução
Quando várias bibliotecas usam objetos similares, `typing.Protocol` descreve comportamento esperado, como método `total() -> Decimal`. Isso ajuda a evolução sem herança obrigatória. Verificadores estáticos podem apontar implementações faltantes, mas testes em execução continuam necessários. Introduza abstração quando há segunda implementação real ou uma fronteira clara; antecipar toda possibilidade torna código difícil para iniciantes e colegas.
## Verifique e pratique
Modele um produto e dois itens de pedido. Explique onde validar quantidade e onde calcular total. Na atividade, crie uma dataclass de coordenada com `x` e `y` e função que calcula distância ao ponto de origem. Teste ponto zero e um triângulo 3-4-5. Diga por que um campo lista precisa de `default_factory`.
